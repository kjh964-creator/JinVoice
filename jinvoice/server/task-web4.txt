JinVoice 웹 로그인 후 동작을 실제로 시험해 줘. 승인 없이 진행. 비밀값(secret_key, 쿠키 값, 접속 키)은 절대 출력하지 마. 설정 파일은 읽기만 하고 아무것도 바꾸지 마.

1. D:/0.make/appsite/data/config.json 의 secret_key 로 관리자용 쿠키 값을 만들어 (파이썬):
   import hmac,hashlib,time; exp=int(time.time())+600; sig=hmac.new(secret.encode(), b"jinvoice-admin|"+str(exp).encode(), hashlib.sha256).hexdigest(); cookie=f"jv_admin={exp}.{sig}"
2. 이 쿠키를 붙여서 https://imist.co.kr 로(밖으로 나갔다 들어오는 실제 경로) 요청:
   a) GET /jinvoice/app/ → 코드, HTML 에 '/jinvoice/app/assets/' 포함 여부
   b) GET /jinvoice/app/health → 코드와 JSON
   c) GET /jinvoice/app/profiles → 코드와 목소리 이름 목록
   d) GET /jinvoice/app/history?limit=5 → 코드와 개수
   e) WebSocket wss://imist.co.kr/jinvoice/app/ws/events 연결이 되는지 (파이썬 websockets 또는 aiohttp 로, 같은 쿠키 + Origin: https://imist.co.kr 헤더). 안 되면 오류 메시지 요약.
3. 음성 실제 생성 시험(CPU라 느릴 수 있음, 최대 10분 기다림): 앱 화면이 쓰는 생성 API 를 backend/api/routers/generation.py 에서 확인해서, 목소리 '김진호'(없으면 첫 번째 목소리)로 '안녕하세요. 진보이스 웹 시험입니다.' 를 생성. 요청은 https://imist.co.kr/jinvoice/app/... 로, 같은 쿠키와 Origin: https://imist.co.kr 헤더를 붙여서.
   - 모델 라이선스 동의가 필요하다는 오류가 나오면 동의하지 말고 그 오류 문구만 보고.
   - 성공하면 걸린 시간(초), 결과 오디오 길이(초), 생성 중 서버 프로세스 최대 메모리(MB), PC 남은 RAM 최저값 보고. 결과 WAV 의 최대 음량(peak)과 RMS(dBFS)도 계산해서 보고.
4. 다른 서비스(/, /app/, /webhard/) 가 시험 중에도 200 인지 마지막에 한 번 확인.
